# dep-visualizer

CLI-инструмент для построения и визуализации графа зависимостей
npm-пакетов (практическая работа №2, вариант 11). Данные о зависимостях
берутся напрямую из npm registry по HTTP, без менеджеров пакетов и
сторонних библиотек.

Требуется Python 3.11 или новее (используется встроенный модуль
`tomllib`). Сторонние зависимости не нужны.

## Структура

| Путь | Назначение |
|------|------------|
| `src/main.py` | точка входа, выбор источника данных, вывод |
| `src/config.py` | загрузка и проверка конфигурации TOML |
| `src/registry.py` | получение прямых зависимостей из npm registry |
| `src/graph_file.py` | чтение файла тестового репозитория |
| `src/graph.py` | построение графа (DFS без рекурсии), циклы, обратные зависимости |
| `tests/` | модульные тесты (`unittest`) |
| `tests/data/` | тестовые графы и примеры конфигураций |
| `config.toml` | пример конфигурации |
| `run.bat`, `run.sh` | скрипты запуска приложения и тестов |

## Конфигурация

Параметры задаются в TOML-файле. Все параметры обязательны, лишние
параметры считаются ошибкой.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `package` | строка | имя анализируемого пакета |
| `repository` | строка | URL npm registry или путь к файлу тестового репозитория |
| `test_mode` | bool | `true` — работа с тестовым репозиторием из файла |
| `ascii_tree` | bool | `true` — выводить зависимости в виде ASCII-дерева |
| `filter_substring` | строка | пакеты, имя которых содержит подстроку, не учитываются; `""` — без фильтра |
| `reverse_for` | строка | пакет, для которого выводятся обратные зависимости; `""` — вывести граф |

Пример (`config.toml`):

```toml
package = "express"
repository = "https://registry.npmjs.org"
test_mode = false
ascii_tree = true
filter_substring = "debug"
reverse_for = ""
```

### Проверки параметров

- файл конфигурации существует и является корректным TOML;
- присутствуют все параметры и нет неизвестных;
- `test_mode` и `ascii_tree` — логические значения, остальные — строки;
- `package` не пустой, не длиннее 214 символов; в обычном режиме —
  допустимое имя npm-пакета (в том числе `@scope/name`), в тестовом —
  заглавные латинские буквы (`A`, `B`, `AB`);
- `repository` в обычном режиме — URL со схемой `http` или `https`,
  в тестовом — существующий файл; относительный путь отсчитывается от
  папки, где лежит конфигурационный файл;
- `filter_substring` не содержит пробельных символов и не входит в имя
  самого анализируемого пакета;
- `reverse_for`, если не пустой, проверяется по тем же правилам, что и
  `package`, и не должен исключаться фильтром.

При ошибке все найденные проблемы выводятся в stderr.

## Получение зависимостей из npm

Для пакета запрашивается манифест последней версии:

```
GET {repository}/{package}/latest
```

У scoped-пакетов слеш кодируется: `@babel/core` → `@babel%2Fcore`.
Из ответа (JSON) берётся поле `dependencies`, поля `devDependencies`,
`peerDependencies` и `optionalDependencies` не учитываются. Алиасы вида
`"string-width-cjs": "npm:string-width@^4.2.0"` заменяются настоящим
именем пакета (`string-width`). Запрос выполняется стандартным
`urllib.request` с таймаутом 15 секунд.

Обрабатываемые ошибки: пакет не найден (HTTP 404), другие HTTP-ошибки,
отсутствие соединения, таймаут, ответ не в формате JSON, неверная
структура ответа.

Во время загрузки в stderr выводится число загруженных пакетов.

## Тестовый репозиторий

При `test_mode = true` параметр `repository` — путь к текстовому файлу с
описанием графа. Каждая непустая строка имеет вид `ИМЯ: ЗАВИСИМОСТИ`,
имена — заглавные латинские буквы:

```
A: B C
B: D
C: D
```

Пакет, который встречается только как зависимость (здесь `D`), считается
пакетом без зависимостей. Ошибки формата: строка без двоеточия, имя не
из заглавных букв, повторное описание пакета, повтор зависимости в одной
строке. Если корневого пакета нет в файле, выводится «пакет не найден».

## Построение графа

Граф строится обходом в глубину (DFS) без рекурсии, с явным стеком:

1. в стек кладётся корневой пакет;
2. из стека снимается пакет; если он уже есть в графе, он пропускается;
3. запрашиваются его прямые зависимости; пакеты, имя которых содержит
   `filter_substring`, отбрасываются и не обходятся;
4. оставшиеся зависимости записываются как рёбра и кладутся в стек
   в обратном порядке, чтобы первой обходилась первая зависимость.

Каждый пакет запрашивается ровно один раз, поэтому общие зависимости и
циклы не приводят к повторной загрузке и бесконечному обходу. Рёбра,
ведущие в уже посещённый пакет, при этом сохраняются.

Циклы ищутся отдельным нерекурсивным DFS по построенному графу: на стеке
лежат пары «пакет, итератор по зависимостям», и ребро в пакет, который
ещё находится на стеке, замыкает цикл. Такие рёбра выводятся отдельно.

## Обратные зависимости

Если `reverse_for` не пустой, вместо графа выводятся пакеты, которые
прямо или транзитивно зависят от указанного пакета:

1. строится граф зависимостей корневого пакета `package` (как выше);
2. рёбра графа разворачиваются: для каждого пакета — список пакетов,
   которые от него напрямую зависят;
3. по развёрнутым рёбрам из пакета `reverse_for` выполняется тот же
   обход в глубину без рекурсии (`build_graph`), что и при построении
   графа. Все посещённые пакеты, кроме начального, зависят от него.

Поиск ведётся внутри графа пакета `package`: весь npm registry обойти
невозможно, поэтому «кто зависит от пакета» означает «кто из
зависимостей `package` (включая сам `package`) зависит от него».
Если пакет входит в цикл, дополнительно выводится, что он зависит сам
от себя. Если пакета нет в графе, выводится ошибка.

### Коды возврата

| Код | Значение |
|-----|----------|
| 0 | успешно |
| 1 | ошибка конфигурации |
| 2 | ошибка получения данных или пакет `reverse_for` не входит в граф |

## Запуск

Windows:

```bat
run.bat
run.bat --config путь\к\config.toml
```

Linux / macOS:

```sh
./run.sh --config path/to/config.toml
```

Напрямую: `python -m src.main --config config.toml`. Без `--config`
используется `config.toml` из текущей папки.

## Тесты

```sh
run.bat test
./run.sh test
python -m unittest discover -s tests -v
```

Тесты registry не обращаются к сети: `urlopen` подменяется через
`unittest.mock`.

Проверка стиля (необязательно):

```sh
pip install -r requirements-dev.txt
flake8 --max-line-length 80 --max-complexity 10 src tests
```

## Примеры

### Тестовые репозитории

Все конфигурации лежат в `tests/data/`:

| Конфигурация | Граф | Что показывает |
|--------------|------|----------------|
| `graph_linear.toml` | `linear.txt` | цепочка A → B → C → D |
| `good_test_mode.toml` | `diamond.txt` | общая зависимость D загружается один раз |
| `graph_cycle.toml` | `cycle.txt` | цикл A → B → C → A |
| `graph_self_loop.toml` | `self_loop.txt` | пакет зависит от самого себя |
| `graph_complex.toml` | `complex.txt` | большой граф с циклом |
| `graph_complex_filter.toml` | `complex.txt` | фильтр `F` |
| `graph_from_middle.toml` | `complex.txt` | корень в середине графа |
| `graph_missing_root.toml` | `diamond.txt` | корневого пакета нет |
| `graph_bad_*.toml` | `bad_graph_*.txt` | ошибки формата файла |

  C -> A

| Конфигурация | Граф | Пакет | Что показывает |
